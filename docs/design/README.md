## Working method

1. Define the desired investigative product.
2. Freeze the legacy system's observed behavior without redesigning it.
3. Classify legacy behavior as keep, correct, replace, remove, or unresolved.
   No behavior defaults to keep; each one needs independent target rationale.
4. Define source contracts, the evidence model, graph ontology, and
   calculation contracts.
5. Prove critical graph queries and change propagation against the real corpus.
6. Write the target architecture and vertical-slice roadmap.
7. Create the rebuild branch, move the legacy runtime into `archive/` in one
   rename-only commit, and build from a clean root. Compare outputs against the
   frozen legacy evidence and preserve a tested rollback path.
